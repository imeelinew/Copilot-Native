# 实时面试项目资料

当前整理了轻购（mobile-shop）和城市视图（datapilot-rebuild）的60张资料卡，覆盖主要页面、业务流程、请求层、状态、组件通信、异常处理、部署和实现边界。源码位置与SHA-256保存于应用内置的 `Copilot Native/Resources/ProjectFacts.json`；[覆盖清单](../knowledge/project-coverage.md)可逐模块阅读。

## 如何使用

实时面试沿用“回答背景”的自动匹配、轻购、城市视图、通用面试题。明确讨论某个项目时选择对应背景，自动模式也识别项目名及购物车、搜索联想、仪表盘等功能词。连续追问沿用最近问题和已检索的功能主题；明确切换项目名会重新选择项目，通用模式排除项目事实。

每次问题先用本地关键词和可用的中文向量检索，再补入相邻实现的资料。最多10条、正文与边界合计8000字符。实际模型收到的是相关功能的流程、关键函数、参数和边界，以及近期对话；不会把整个仓库每次上传。现有模型服务会接收这些检索结果，检索向量在本机生成。

资料注明当前代码能证明什么。例如轻购没有Pinia和自动刷新Token；城市权限树配置不直接生成路由，3D本地沙盘不等于真实数字孪生。模型可解释代码作用与可考虑的改进，不能把后端未知能力、团队职责、线上事故或性能数字说成已证实经历。

## 更新与来源

应用优先加载随构建发布的资料快照，不依赖旧外部27条事实文件；只有资源不存在时才兼容读取 `~/Resumes/AI面试知识库/项目事实.json`。通用题库位置维持原状。相对源码路径按 `~/Dev/<project>/` 解析。

载入时和每次检索前都重新核对源码哈希。修改或删除源码后对应旧资料会被排除并提示；点击刷新只是重新载入并建索引，**不会自动给变化的代码盖章**。需要重新阅读修改后的实现，更新相关内容、边界、位置及哈希，再构建发布。已有缓存的向量按资料指纹失效重算。

范围：覆盖可执行业务模块及相关类型/配置；不把样式、图片、依赖目录、占位页、未使用的GlowRing组件、环境密钥或旧简历描述当作已实现功能。个人职责未确认；源码覆盖不保证所有开放式问题都有答案。

## 验证

- `python3 scripts/validate-project-knowledge.py`：核对所有来源、哈希、位置、同项目关联和事实边界；不会自动更新哈希。
- `python3 scripts/validate-project-knowledge.py --write-report`：校验后重建人读的覆盖清单。
- `zsh scripts/test-interview-knowledge.sh`：直接运行生产检索代码，测试不同措辞的功能题、项目隔离、比较、连续追问、切换项目及过期/缺失证据；使用内存数据库，不下载模型，不修改用户资料。
- `zsh scripts/test-interview-knowledge.sh --live`：额外使用当前配置的远程模型回答三道项目题；只发送资料快照片段及测试问题，不读取实际屏幕或发送凭证正文。输出需要人工核查，不能以“有回复”视为语义全对。

关键词测试覆盖无向量模型时的最低可用路径，不证明全部自然语言表达或向量排序的正确率。上线后的实际语音识别效果仍取决于音源和转写结果。
