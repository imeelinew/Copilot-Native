# 实时面试

在主窗口工具栏点击「实时面试」。语音识别使用豆包流式语音识别 2.0 小时版，连接双向流式优化接口 `bigmodel_async`，开启句末二遍识别。回答继续使用「设置 → AI 模型」中的配置。

## 使用

1. 在「设置 → 语音识别」填写 API Key。设置自动保存到本机 UserDefaults。
2. 线上会议选择「会议 / 系统声音」。默认识别全部系统声音；点击刷新按钮后可以指定某个正在运行的应用。缺少授权时点击界面的「系统权限」按钮，在 macOS 中允许屏幕与系统音频录制，然后完全退出并重新打开 App。权限检查本身不弹窗，权限失败不会自动重试。程序只接收音频输出，不读取或保存屏幕帧。
3. 识别自己说话时选择「麦克风」，输入设备跟随 macOS 声音设置。系统会请求麦克风权限。
4. 点击「开始监听」，转写会持续更新。确定分句到达后，当前 AI 模型会持续提取完整面试问题，略过寒暄、评价和告别；未完整的提问等待后续分句补充。分析与转写、回答生成分别进行，不会因为背景音或下一句仍在转写而推迟已经完整的问题。界面显示问题分析状态，分析失败时可立即手动提交。
5. 可随时点击「立即回答」，或「编辑问题」修正术语后提交。「忽略」跳过当前待回答文字。关闭自动回答后只转写，手动决定何时提交。
6. 完整问题会先按题目标题匹配已保存题库，忽略常见提问前后缀，优先当前选中的 Package / Capsule；匹配唯一时直接展示原文，标注“来自已保存题库”，不调用模型重写。普通自我介绍请求支持口语别名并在本地识别，不依赖远程问题分析；多版本无法确定时提示选择题库，不编造姓名、学校等个人信息。限定时长、英文介绍及自我介绍后的追问仍走问题分析。其他问题会检索当前选择的本地项目资料，并带上最近四轮已完成问答理解追问。新问题会取消仍在生成的旧回答，旧问题可重新生成。
7. 回答完成后可复制，或保存到当前 Package / Capsule 下的题库。主窗口和浮窗共享同一份会话，隐藏或关闭主窗口不会停止监听或清空问答；完全退出应用后本次问答不保留，需要长期保存的请存入题库。

默认热词已按前端面试方向配置 299 个词，覆盖 Vue / React、TypeScript、工程化、可视化、三个业务项目及桌面开源项目。核心词靠前；词库会去重，最多提交 5,000 个词。豆包一遍流式识别只使用前 100 tokens，完整词库供已开启的二遍识别使用。热词通过 `request.corpus.context` 提交，修改后重新开始监听生效。

## Dock 与悬浮答案

运行时隐藏 Dock 图标（也不出现在 Command-Tab 列表）。通过全局快捷键返回应用；也可重新打开 `/Applications/Copilot Native.app` 显示主窗口，在应用菜单中退出。隐藏窗口不等于退出程序，监听会继续，停止监听请按对应快捷键。

在实时面试页先选好音源、会议应用及项目背景，再点击“悬浮面试答案”或按 ⌃⌥⌘I。浮窗置顶、可拖动和缩放，显示监听状态、待提交问题、所选历史问题及流式答案；新问题仍按原流程自动生成。它不接受键盘焦点，浏览器或编辑器继续接收输入。主窗口和浮窗中均能展开完整快捷键说明。

⌃ 表示 Control，⌥ 表示 Option，⌘ 表示 Command。以下快捷键在其他应用内也有效：

| 快捷键 | 操作 |
| --- | --- |
| ⌃⌥⌘I | 打开／收起实时面试浮窗，首次使用会切换到面试浮窗模式 |
| ⌃⌥⌘Space | 显示／收起当前窗口或当前模式的浮窗 |
| ⌃⌥⌘M | 返回实时面试主窗口，可调整音源、项目和设置 |
| ⌃⌥⌘L | 开始／停止监听；停止时仍按原流程收取最后转写 |
| ⌃⌥⌘A | 提交当前待回答问题（编辑中则提交编辑文字） |
| ⌃⌥⌘P | 暂停／恢复自动回答；继续转写，不取消已经生成中的回答 |
| ⌃⌥⌘X | 停止当前答案生成；继续监听，新问题仍可自动生成 |
| ⌃⌥⌘R | 重新生成当前所选题目的答案 |
| ⌃⌥⌘D | 忽略待提交文字；保留已生成问答 |
| ⌃⌥⌘←／→ | 查看上一题／下一题，到首尾不循环 |
| ⌃⌥⌘↑／↓ | 上下滚动当前浮窗答案 |

原有 ⇧⌘L 和 ⇧⌘Return 继续用于实时面试主窗口。截图功能的 ⌃⌥⌘S、Return、⌫、E 维持原义，不用于提交面试问题。截图浮窗和面试浮窗互斥显示，Space 与上下滚动按当前浮窗模式分发。热键占用或注册失败会显示提示。

新浮窗在第一次显示前设置共享排除；即使关闭普通窗口的共享隐藏选项，答案浮窗仍请求排除。其保护方式沿用截图浮窗，但是否被具体录屏客户端尊重仍须在腾讯会议接收端确认，保持“视频流畅度优先”关闭。Dock 隐藏不会隐藏系统权限提示等系统界面。

验证：`zsh scripts/test-live-interview-panel.sh` 离线测试真实面试控制器、面板隐私/非激活属性、历史导航、隐藏/关闭重开和共享滚动路由，不启动实际录音或远程识别会话。

## 异常处理

- 停止监听时先结束采集、发送剩余音频和结束包，最多等待 4 秒收取最终转写。
- 短暂网络异常自动重连，最多连续重试 4 次。麦克风设备变化会重建采集与识别会话。
- 重连期间不补录声音，界面会提示重述遗漏内容。未提交文字保留在编辑框里供核对。
- 收发队列有上限，发送积压时明确报错并恢复连接，避免静默丢弃音频。
- 授权失败、余额不足等服务错误会停止监听并显示错误；回答模型失败可以单独重试。
- 问题分析失败后每隔 1 秒主动重试，最多重试 2 次，不依赖后续音频回调。连续失败保留原始待提交文字，主窗口与浮窗显示错误及 ⌃⌥⌘A 手动提交提示。手动提交、编辑、忽略、暂停自动回答或停止监听会取消正在等待的分析重试。
- 语音结果只包含后续分句时保留此前确认分句，后来的临时分句不覆盖已确认文字。
- 所选会议应用关闭后，请停止监听并刷新应用列表，或选择全部系统声音。

## 发言处理

所有采集到的语音统一作为面试官发言，不猜测说话人身份，也不按“候选人回答”过滤。仍区分完整问题、未完成的提问背景和寒暄。只想接收对方时选择会议应用声音；选择麦克风时，自己说的话也按面试官发言处理。

### 说话人分离（能力核实，尚未接入）

官方流式 ASR 接口提供 `enable_speaker_info=true`，默认关闭；搭配 `show_utterances=true` 返回说话人 ID，推荐使用 2.0 模型。当前应用尚未开启此参数、解析身份或把候选人的真实口述作为角色上下文。说话人 ID 仍需映射为面试官／候选人；腾讯会议场景也可通过系统声音与本机麦克风两路音源区分。控制台账户的实际开通状态需登录核实。

[官方流式接口及说话人参数](https://docs.volcengine.com/docs/DoubaoVoice/bidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)

## 题库与自动提交回归（2026-10-20）

`scripts/test-live-interview-panel.sh` 使用内存题库和合成转写验证：无 AI 配置时自我介绍原文返回、题库版本按范围选择、限定语言／时长不误用普通介绍、临时分句转确认、尾部分句更新保留前文、没有新增音频时分析失败仍主动重试、三次失败后保留文字供手动提交、手动提交／忽略取消重试。测试不录音、不发网络请求。

另以当前已配置模型运行生产问题提取器，合成 React 技术提问、开场通勤寒暄、限时自我介绍分别得到 answer／ignore／answer。此验证未发送个人题库或实际音频，也不代表全部真实会议场景均已覆盖。

实际追问“这几个页面里哪个开发难度高”暴露了另一处解析问题：模型可能把时间戳编号作为数字字符串返回，如 `"18740"`。修复后兼容整数和整数字符串，以及两者混合的数组；仍拒绝未知编号、非整数、布尔或空值，不允许错误编号消耗转写。格式错误改为中文说明。离线回归覆盖解析及控制器自动提交链路。

## 在线验证（2026-10-14）

使用公开中文语音，以每包 200 ms、接近正常说话速度发送到真实服务。

| 来源 | 音频时长 | 最终转写 |
| --- | --- | --- |
| [SenseVoice 官方中文示例](https://huggingface.co/FunAudioLLM/SenseVoiceSmall/blob/main/example/zh.mp3) | 5.62 秒 | 开放时间早上9点至下午5点。 |
| [Qwen3-ASR 官方中文示例](https://qianwen-res.oss-cn-beijing.aliyuncs.com/Qwen3-ASR-Repo/asr_zh.wav) | 4.20 秒 | 甚至出现交易几乎停滞的情况。 |

第二段还使用本项目的 `DoubaoSpeechConnection` 源码编译成独立命令行工具复核，验证了 Swift WebSocket 传输、gzip 封包/解包和结果解析：开始发送后约 1.29 秒收到首段文字，约 5.01 秒收到确定分句。该数值包含音频本身的起始静音与服务处理时间，不等同于模型纯推理延迟。

这是少量清晰普通话素材的连通和流式行为验证，不是识别准确率基准。技术词混说、噪声、口音、macOS 权限交互及真实会议音频采集还需在实际使用环境中确认。自动提交现在使用确定分句和独立的语义提取请求；语义分类仍可能出错，需要时可关闭自动回答或编辑问题后手动提交。

## 本地开发签名与录音授权

本机 Debug / Release 构建使用现有 Apple Development 证书及 `5Q5QT76MJU` 团队签名，Xcode 配置和 `project.yml` 保持一致。常规运行构建不要传 `CODE_SIGNING_ALLOWED=NO`，该参数只用于纯编译检查；关闭签名的产物用于运行时，需要重新执行开发证书签名。

macOS 授权记录会校验 App 的签名身份。临时签名随重建发生变化时，即使设置页显示开关已打开，系统仍可能拒绝当前二进制。2026-10-14 日志明确记录了该 App 的 `Failed to match existing code requirement`。已切换稳定证书签名，旧录屏授权需要重新授予一次；后续签名身份校验已通过，跨重建的实际 TCC 授权保留尚未在用户操作中验证。

## 模拟面试视频验证（2026-10-14）

使用用户提供的 93.13 秒模拟面试视频，经本项目豆包连接代码按每包 200 ms 实时回放音轨，记录了 214 次识别更新、13 个确认分句。原先逻辑会在 ASR 已经判停后再等待一轮 1.2 秒静音，音量回升或后续文字更新又取消提交，导致连续对话下问题迟迟不生成；同时首段的零起始时间被 ASR 省略，旧代码会漏掉这一段。

修复后，对同一转写记录运行本项目的问题提取器，识别出自我介绍、项目职责、困难项目、时间管理、同事与跨部门合作、个人优势、离职原因、空窗期、薪资、到岗与反问等 10 轮面试问题，略过 3 段开场/结束闲聊。最终复核的问题提取耗时约 1.11～2.11 秒，中位约 1.35 秒，计时从请求问题分析开始，不含语音识别延迟。另验证了结束寒暄、普通问候、不完整问题、跨分句的 Vue 2/3 问题、候选人陈述及正式 offer 提问的分类。

单独验证视频中的时间管理问题，现有回答客户端约 1.43 秒出现首字、7.07 秒完成回答。此验证使用空资料上下文，只验证远程回答链路，不代表本地资料检索耗时，也不代表实际腾讯会议采集的端到端延迟。语音识别和语义提取仍有各自的延迟。
